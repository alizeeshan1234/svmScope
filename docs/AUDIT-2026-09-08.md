# svmscope audit — 2026-09-08

Pre-PR review of the tree at `435e963`, run as four independent read-only
passes (engine + runtime hook, profiler + symbol data, decoding + mutations,
server + CLI + packaging). Every finding below was verified against the code
by the reviewer that found it; the top four were re-verified by hand.
No code was changed by the audit.

## Verdict

Not PR-ready as-is. The architecture is sound and the alignment logic the
last three reviews hammered on (frame/span pairing, post-order snapshot
ranking, `inner_exact`) is correct. What remains is a short list of real
bugs, mostly at the edges, plus documentation that lags the code. Fix the
blockers below and it meets a "code quality is good" bar.

## Status — round 1 (commit `bd61064`, 13:51)

high-priority items this audit missed (loss invariants measured from the

## Verdict after three rounds

Production-ready for what it claims. Every correctness finding from both
audits is closed and verified; what remains is one refactor and the
documented, disclosed fidelity boundary (historical account state needs an

## Blockers (fix before the PR)

| # | Where | Finding |
|---|---|---|
| B1 | `src/scope.rs:1352`, `src/replay.rs:2473` | **Precompile blind spot.** Ed25519/secp256k1 instructions emit no `invoke` log and never reach the runtime hook, so every step after one is shifted by one: wrong logs/CU on the precompile step, none on the next, and CPI snapshots of instruction N+1 attributed to N. Reachable by any transaction with a signature-verify precompile. Fix: key inner snapshots on the index `after_instruction` already receives, and make `spans_for` skip precompile indexes. |
| B2 | `src/idl.rs:667`, `:323`, `:747` | **Release-mode panic on a hostile IDL.** `offset + size` unchecked; an on-chain IDL declaring `[u64; 2^61-1]` wraps and slices `data[8..0]`. Fix: `checked_add` at all three sites. |
| B3 | `server/src/main.rs:1179` → `src/search.rs:38` | **Panic from one GET.** `/counterfactual/{sig}?lo=5&hi=1` hits `assert!(lo <= hi)` inside `spawn_blocking`; caller gets a 500 with the panic text. Fix: validate and return 400. |
| B4 | `src/replay.rs:2036-2078` | **Silent mutation-ordering bug.** Offset patches (`ixarg`) are applied before wholesale replaces (`ixdata`) regardless of listed order, so an `ixarg` alongside an `ixdata` on the same instruction is silently discarded. Fix: apply in listed order, or reject the combination. |
| B5 | `src/profile.rs:179`, `:759` | **Corpus mislabels tiny functions.** No length floor: 71 bundled shapes are ≤4 instructions (two-slot getters like `ldxdw r0,[r1+off]; exit`) and will rename any program's identical getter to a Phoenix trait method. Exact-tier index is last-wins on hash collision with no ambiguity guard. Fix: length floor (~8 slots) and drop colliding `full` hashes. |
| B6 | `symbols/corpus.jsonl.gz` | **Corpus regressed.** 0 of 3742 entries carry `opcodes`; the `≈` tier is unreachable with shipped data (dropped when the corpus was rewritten for the `__rustc[...]` name fix). Fix: regenerate via `symbols dump` from the harvested builds, or remove the tier. |
| B7 | `server/src/main.rs:618,699` | **Symbol upload broken above ~1.5 MB.** No `DefaultBodyLimit`; axum's 2 MB default rejects real `.debug` files before the handler runs. `MAX_SYMBOL_BYTES = 32 MB` is dead. Fix: `DefaultBodyLimit::max(...)` on the profile route. |
| B8 | `vendor/.../invoke_context.rs:548`, `lib.rs:38-50` | **Hook semantics.** `Exit` reports `ok` before `pop()`, where `UnbalancedInstruction` is raised, so an unbalanced CPI is reported ok. `fire` holds the `RefCell` borrow while calling the hook; a hook calling `clear()` panics inside the runtime. No RAII guard, so a panic leaves the closure installed on the thread. Fix: fire after pop with the combined result, drop the borrow before calling, return a guard from `set`. |
| B9 | `server/src/main.rs:1337`, `guard.rs:85` | **Rate limiter and stats keyed on unverified `X-Forwarded-For`.** Self-hosted without a proxy, a client mints a new identity per request; identities are never pruned and are flushed to disk every 5s. Fix: trust XFF only behind a configured proxy flag. |
| B10 | `server/Cargo.toml:16` | **Workspace does not build against upstream.** The server hard-requires `single-run-trace`, which needs the LiteSVM fork and the vendored runtime. The maintainer's tree will not build the workspace. Fix: make the feature optional for the server with a clear fallback, and say so in README. |

## Should fix (a strict reviewer will flag)

- `src/idl.rs:292` `find_ix` prefix-matches with no length requirement; a malformed 1-byte discriminator shadows every 8-byte one. Require exact length per dialect.
- `src/replay.rs:2519` and `src/scope.rs:1342` parse `format!("{:?}", err)` to recover the instruction index, two different parsers. Depend on `solana-transaction-error` and `match`.
- `src/scope.rs:1714` single-run mode attaches the transaction's final `return_data` to every step of that program; the `i == 0` clause is dead.
- `src/trace.rs:377` `spans_from_logs` accepts `Program log: ... invoke [1]` as a span; a chatty program can shift attribution. Skip `log:`/`data:`/`return:` lines first.
- `src/scope.rs:1310` `original_index` ignores `MoveIx`, so a move-only re-run compares the wrong rows.
- `src/profile.rs:712` corpus names cannot be overridden by the user's own `.debug`; the three symbolizers disagree on precedence.
- `src/profile.rs:860-904` and `elf_parse`: unchecked `off + size` on section/symbol fields; debug builds panic on a crafted ELF.
- `src/profile.rs:1001` `function_map` cache keyed on length + 64 sampled windows, never evicted; two programs can share one map.
- `server/src/main.rs:913` world cache: up to 48 full `Replay` clones with every ELF, cloned again per hit; `clear()` at 48 silently breaks the "same world" guarantee with no signal in the response.
- `server/src/main.rs:100` SSRF check bypassed by URL userinfo (`evil.com:80@127.0.0.1`) when custom RPC is enabled.
- Dead second match arm in `apply_mutation` (`replay.rs:1598`); three integer encoders (`idl.rs:754`, `replay.rs:1509`, `idl_encode.rs:157`) and two hex decoders with divergent rules; the setup sequence `fresh_svm → resolve → apply → tx_with_mutations` written four times; `trace()` is ~520 lines with five closures inside the loop.
- Feature-gate shape: `#[cfg] { return }` + `allow(unreachable_code)`, `InnerSnapshot` compiled unconditionally with a `dead_code` allow, `Phase::Enter` delivered with a meaningless `ok`.
- `ixname.rs:492` Anchor account groups shift every following role name; `token_ix` omits `InitializeMultisig`.
- `profile.rs:1096` per-instruction `Vec<String>` + `join(";")` map lookups: ~11M string clones on a 1.4M-instruction transaction.

- README `svmscope = "0.4"` cannot resolve to anything documented below it.
- README roadmap lists `Mutation::field` and archival state as unshipped; both shipped.
- `MutationInput` doc lists every `kind` except `ixarg`; the `SkipIx` variant inherits `IxArg`'s orphaned doc; `SkipIx` and `MoveIx` docs disagree on whether indexes are pre- or post-skip; `Field` says int/bool but rejects JSON `true`.
- Stale "prefix replay" / "until the runtime hook lands" / "hosted server" comments in `trace.rs`, `scope.rs`, `replay.rs`; `attach_names` carries `attach_compute`'s doc; `InnerSnapshot` has two summaries; `by_similarity` doc says 10%, code says `max(2.0)`.
- `/api` index lists 10 of 21 routes; README omits six env vars the server reads and says it binds 127.0.0.1 (it binds 0.0.0.0); MSRV comment says 1.91, manifest says 1.93.

- Personal deployment artefacts in the tree: keepalive cron for the Render URL, corpus workflow cloning a personal repo, Dockerfile copying gitignored `static/.env.local`.
